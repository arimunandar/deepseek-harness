# Agent Note: per-provider default models

Status: implemented

[English](2026-08-26-per-provider-default-models.md) | 中文

## Problem

切换到某个提供方时，并没有说明要切换到它的哪一个模型。

`agent-default-model` 为整个部署只持有一份选择——提供方与模型绑在一起。于是每一个改变提供方的手势都得自己把模型那一半编出来：[连接目录](2026-08-26-connect-your-ai-directory.zh.md)的"用于新对话"为每个已配置连接携带一个 `defaultModel`，而没有连接卡片的提供方则根本没有答案。

这个空缺无法从任何东西推导出来。每个随附目录都按它自己的顺序列出模型——对所有目录而言都是字母序——所以"第一个模型"对 Anthropic 是 `claude-fable-5`，对 OpenAI 是 `gpt-4`。没有旗舰标记，没有发布日期，也没有任何有意义的排序。

模型页还有另一个不相干的空缺：一行只显示提供方的名字，别无其他。两条经由不同适配器服务同一家厂商的路由——`llm-deepseek` 上的 `deepseek-official` 与 pi-ai 目录路由 `deepseek`，两者都读 `DEEPSEEK_API_KEY`——呈现为两行，而它们的名字只有大小写之差。

## Decision

`agent-default-model` 新增 `perProvider`：一张以路由为键的模型 id 映射，并在既有选择旁边提供 `modelFor`、`saveProviderDefault` 与 `clearProviderDefault`。它落在这里而不是各适配器自己的 profile 里，因为这个问题与适配器无关，而那个包本来就拥有"我们从哪个模型开始"；把它放进 `llm-pi-ai` 和 `llm-deepseek` 会把一个概念复制进两份 schema。

缺省的条目就保持缺省。没有任何东西去播种一个猜测，`modelFor` 回答 undefined，于是每个调用方保留自己的兜底——`connections.activate()` 优先采用已记录的默认值，而不是它的配置所随附的 `defaultModel`，把随附值当作起点而非偏好。

`saveSelection` 在它的整段写入中把这张映射带上。那次写入的存在意义，是清除新模型并不具备的已存推理档位；连带丢掉每条路由的默认值则不是。这次携带以"是否为空"为判据，而不是"是否缺省"，因为 schema 会把该 dict 物化——正是这个形状造成了[连接的 `routePath` 缺陷](2026-08-26-connect-your-ai-directory.zh.md)，那里一个 `=== undefined` 判断从来不成立。

现在模型页的每一行陈述三个此前被隐去的事实：该路由从哪个模型开始，呈现为一个覆盖该路由自身目录的选择器；它的 profile 所指定的接口地址，或者说明适配器自己的那个生效；以及拥有它的适配器。适配器标签正是把 `DeepSeek` 和 `deepseek` 区分开的东西。

### 未声明 token 的缺陷，以及现在能抓住它的门禁

连接页面上线时，每一处颜色命名的都是主题样式表从未声明的变量——`--dsw-alias-text-primary`、`bg-secondary`、`text-link` 以及其余，全是"看起来像那么回事"的空名字。未声明的自定义属性没有兜底，因此那些声明干脆不生效：卡片渲染出来没有表面、没有边框、没有背景——这就是"这个 UI 很糟"的实际所指。

模型页从来没有这个缺陷，因为那里有一个测试会把每一处 `var(--dsw-*)` 与主题样式表比对。那道门禁现在也进了连接包，旁边还有一个断言共享行表面的测试。一个被误用时毫无声响的设计系统，需要在每个使用它的地方设检查，而不只是在它最初被写下的地方。

## Alternatives considered

**从目录推导默认值。** 取第一条、或最后一条、或版本号最高的那条。否决，因为可用的排序全是字母序："第一条"是 `gpt-4` 和 `claude-fable-5`；而要在 `gpt-5.6-terra`、`claude-opus-4-5-20251101` 和 `mimo-v2.5-pro-ultraspeed` 之间解析版本，那是一个打扮成规则的猜测。一个看起来像推导出来的错误默认值，比没有默认值更糟，因为没人会想到去核对它。

**存进各适配器的提供方 profile。** `llm-pi-ai.providers.<route>.defaultModel` 与 `llm-deepseek.defaultModel` 会把值放在它所描述的路由旁边。否决，因为那会把一个概念复制进两份随后必然漂移的 schema，而且第三个适配器还得记着补上它。选择的所有者本来就存在。

**改为给每个提供方播种一份 `models:` 列表。** 否决，这是对诉求的误读：目录路由本来就服务它的整个目录，写一份显式列表是在收窄所提供的范围，而不是增加一个默认值。

**只修连接页的样式表。** 否决，那只是问题的较小一半。这些 token 之所以是错的，正是因为没有任何东西说它们错了；而同样的错误，距离下一个新页面只有一步之遥。

## Testing

`agent-default-model` 端到端覆盖这张映射：读取一条缺省路由、记录一条而不扰动当前选择或它的同级、在整段选择写入中存活、清除一条，以及在没有挂载设置提供方时仍然可用。

模型页的 store 针对手写文档实际可能产生的 wire 形状受检——不是对象的 section、不是映射的 `perProvider`、非字符串的模型、空字符串——因为该 section 是以 `unknown` 抵达的。一次被拒绝的目录读取会让每一行都保留下来并配一个失效的选择器，而不是让整页失败。

样式门禁把连接样式表里每一处 `var(--dsw-*)` 与主题样式表比对，拒绝兜底位上的字面颜色，并固定共享的行表面。

## Consequences

一个人现在可以为每个提供方指定一次它从哪个模型开始，而每个切换提供方的手势都会遵循它。

这张映射以路由为键，而没有任何东西校验该路由或该模型是否仍然存在。被改名的路由会留下一条悬空条目，被目录撤下的模型会留下一个选择器不再提供的默认值——该行会把它显示为选中值，而背后没有对应选项。两者都不承重：选择仍然经由适配器解析，而适配器会在请求时拒绝未知模型。

`llm.models` 现在是模型页加载中的第四次读取。它是一次增益——被拒绝只损失选择器，不损失页面——但对一个本来已经发起三次往返的界面来说，这是又一次往返。
